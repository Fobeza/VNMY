# Как добавлять контент (для человека и ИИ)

Проект: движок визуальных новелл, всё на статике. **Новый контент — это только
новые папки и JSON-файлы в `stories/`**, код трогать не нужно.

## Понятия

| Сущность | Где лежит | Что это |
|---|---|---|
| **Вселенная** | `stories/<id>/universe.json` | мир: название, описание, обложка, акцент. Первый экран приложения |
| **Новелла** | `stories/<вселенная>/novels/<id>/story.json` | одна история: персонажи, сцены, шаги |
| **Сцена** | внутри `story.json` → `scenes[]` | фон + погода + состав персонажей + список шагов |
| **Шаг** | внутри сцены → `steps[]` | одна реплика, выбор, переход, финал |

Иерархия жёсткая: новелла всегда внутри вселенной. Если вселенная не нужна —
она всё равно есть: используйте «Без вселенной» (в файлах это `"universe": ""`,
но лучше просто завести одну вселенную).

## 1. Новая вселенная

Создайте папку и файл:

```
stories/nochnoy-gorod/universe.json
stories/nochnoy-gorod/cover.webp        ← необязательно
stories/nochnoy-gorod/novels/           ← сюда пойдут новеллы
```

```json
{
  "schema": 1,
  "id": "nochnoy-gorod",
  "title": "Ночной город",
  "author": "Ваше имя",
  "description": "Одна строка: о чём этот мир.",
  "cover": "cover.webp",
  "accent": "#8fb8d8",
  "order": 10
}
```

- `id` должен совпадать с именем папки; только латиница, цифры, дефис;
- `order` — порядок карточек в библиотеке (меньше = раньше);
- `cover` — путь от папки вселенной; можно оставить пустым, тогда на карточке
  будет первая буква названия;
- `accent` — цвет акцента, готовые варианты: `#e0b072`, `#d98a8a`, `#8fb8d8`,
  `#9ecf9a`, `#b79ae0`, `#d8d2c4`.

Шаблон: `stories/_template/universe.json`.

Затем `npm run build` — вселенная появится на первом экране.

## 2. Новая новелла в существующей вселенной

```
stories/nochnoy-gorod/novels/perekrestok/
├── story.json
└── assets/
    ├── bg-street.webp
    └── hero-neutral.webp
```

Минимальный `story.json`:

```json
{
  "schema": 1,
  "id": "story_perekrestok",
  "title": "Перекрёсток",
  "author": "Ваше имя",
  "description": "Короткая строка для карточки.",
  "cover": "assets/bg-street.webp",
  "accent": "#e0b072",
  "universe": "nochnoy-gorod",
  "characters": [
    {
      "id": "hero",
      "name": "Герой",
      "color": "#e8c08a",
      "sprites": { "neutral": "assets/hero-neutral.webp" }
    }
  ],
  "scenes": [
    {
      "id": "sc_start",
      "name": "Улица",
      "bg": "assets/bg-street.webp",
      "weather": "rain",
      "cast": [{ "char": "hero", "sprite": "neutral", "pos": "center" }],
      "steps": [
        { "id": "t1", "speaker": null, "text": "Дождь не кончался третьи сутки." },
        { "id": "t2", "speaker": "hero", "text": "Мне туда." }
      ]
    }
  ]
}
```

Обязательного минимума почти нет: без `scenes` появится пустая сцена,
без `characters` будут только реплики рассказчика. Но `title` и `scenes` лучше
заполнить сразу. Полная схема — [format.md](format.md).

Шаблон: `stories/_template/novels/novel-example/`.

> `id` новеллы произвольный и должен быть уникален только для удобства. Сейвы и
> прогресс привязаны к `id` новеллы, поэтому при переименовании `id` прогресс
> «теряется» (остаётся в старом ключе).

## 3. Сцены, шаги, выборы, условия

- **Порядок сцен** = порядок в массиве `scenes`. Переход в другую сцену:
  `"goto": "sc_next"` (имя сцены) или `"goto": "sc_next:t3"` (конкретный шаг).
- **Шаг** без `goto` и `end` идёт к следующему шагу сцены; в конце сцены —
  к следующей сцене.
- **Выбор**: шаг с `choices[]`, у каждого варианта `text` и `goto`.
- **Финал**: `"end": true` + `"endTitle": "КОНЕЦ"`.
- **Переменные**: `"vars": [{ "name": "sympathy", "type": "number", "initial": 0 }]`;
  `"set": [{ "var": "sympathy", "op": "add", "value": 1 }]`,
  `"if": "sympathy >= 2"`, `"gotoIf": [{ "when": "sympathy >= 2", "goto": "sc_other:t1" }]`,
  в тексте — подстановка `{sympathy}`.
- Язык условий: `== != > >= < <= && || ! ( )`, слова `and/or/not`, строки,
  числа, `true/false`. Пустое условие = «показывать всегда»; ошибка разбора =
  «не показывать» (и красная подсветка в редакторе). `eval` не используется.
- **Погода**: `none | rain | snow | dust | petals`. **Эффекты** шага: `mood`:
  `shake | flash | blush | dim | zoom`. **Позиция**: `left | center | right`,
  `scale` и `dim` у персонажа на сцене.
- **Пауза**: `"pause": 700` (мс) — «вдох» перед репликой.

Редактор в приложении делает то же самое мышкой/пальцем: вкладки «Шаг»,
«Сцена», «История», «Медиа». Для правок с телефона удобнее он, для массовых
правок — файлы.

## 4. Картинки

| Тип | Размер | Формат |
|---|---|---|
| Фон | 1080×1920 (9:16) | WebP q80, ≈150–250 КБ |
| Спрайт | высота ~1500 px, прозрачность | WebP q92 |
| Обложка новеллы | 9:14 | WebP |
| Обложка вселенной | 4:5 или 9:14 | WebP |

- Кладите в `assets/` **рядом со story.json** и ссылайтесь относительно:
  `"bg": "assets/bg-street.webp"`.
- Можно указать `https://…` или `data:image/…` — тогда файл в папке не нужен,
  но `vnmy.html` вырастет.
- На телефоне картинку можно загрузить прямо в редакторе: он сожмёт в WebP и
  вшьёт в новеллу (`media`), ничего не надо класть в папку.
- Спрайты не искажаются: движок задаёт высоту (`64cqh`), а ширину берёт из
  самой картинки — рисуйте в естественных пропорциях.

## 5. Переименование и удаление

- **Переименовать вселенную**: переименуйте папку и (если у неё нет `id` или
  `id` = старое имя) поправьте `id` в `universe.json` и `universe` у всех
  новелл внутри. Затем `npm run build`.
- **Переименовать новеллу**: переименуйте папку, поправьте `title`; `id` можно
  оставить прежним — прогресс игроков не сломается.
- **Удалить**: удалите папку и запустите `npm run build`.
- Свои вселенные и новеллы (созданные в приложении) живут в браузере:
  удаляются в меню «⋯» на карточке. Перед удалением можно сделать
  «Экспорт вселенной» — это JSON со всеми новеллами и картинками внутри.

## 6. Сборка и проверка

```bash
npm install        # один раз
npm run build      # stories/index.json, bundle.js, stories/builtin.js, vnmy.html
npm test           # 37 проверок: библиотека, игра, редактор, вселенные, file://, один файл
```

Что делает `npm run build` (см. `tools/build.mjs`):

1. обходит `stories/*/universe.json` и `stories/*/novels/*/story.json`
   (папки на `_` и `.` пропускаются);
2. пишет манифест `stories/index.json` — его читает приложение при запуске
   через сервер;
3. пишет `stories/builtin.js` — те же данные обычным скриптом для `file://`;
4. собирает `vnmy.html` — один файл со стилями, движком и картинками в `data:`.

Собранные файлы коммитятся в репозиторий, поэтому играть можно без Node.
Но **после любой правки контента, `js/` или `css/` сборку надо повторить** —
тест свежести сравнивает файлы побайтово.

Посмотреть глазами:

```bash
python3 -m http.server 8000     # затем http://localhost:8000
# или просто открыть vnmy.html в браузере
```

## Инварианты формата

- `schema: 1` у новеллы, `schema: 1` у вселенной.
- `id` вселенной = имя папки, латиница/цифры/дефис.
- `scenes[].id` и `steps[].id` уникальны внутри новеллы (`goto` ссылается на них).
- `characters[].id` уникальны; `cast[].char` ссылается на персонажа.
- `cast[].sprite` — ключ из `characters[].sprites`, по умолчанию `neutral`.
- Все относительные пути — от папки новеллы, без ведущего `/`.
- `universe` новеллы = `id` вселенной; встроенные новеллы сборка помечает сама.
- Нормализация (`js/format.js`) чинит почти всё: пустые сцены, дубли id,
  кривые типы, но **не** угадывает пути к картинкам.

## Если правки нужны в движке

| Задача | Файлы |
|---|---|
| Экран вселенных, карточки, форма вселенной | `js/library.js`, `css/base.css` (`.universe-*`) |
| Экран новелл вселенной, меню новеллы | `js/novels.js` |
| Навигация между экранами | `js/app.js` |
| Хранилище, вселенные, импорт/экспорт | `js/store.js` |
| Схема вселенной / id / «Без вселенной» | `js/universe.js` |
| Схема новеллы, нормализация, `goto` | `js/format.js` |
| Прохождение: меню, журнал, слоты, настройки | `js/player.js`, `css/player.css` |
| Сцена: фон, спрайты, погода, эффекты | `js/engine.js`, `js/weather.js` |
| Редактор и его вкладки | `js/editor.js`, `js/editor-tabs.js`, `js/editor-ui.js`, `css/editor.css` |
| Сборка и манифест | `tools/build.mjs` |
| Тесты | `tests/run.mjs` |

Экран = секция `<section id="screen-…">` в `index.html`; `js/app.js` показывает
нужную и прячет остальные (`show()`), поэтому новый экран = секция + запись в
`SCREENS`.

## Чеклист перед коммитом

1. `npm run build` — без предупреждений о пропущенных папках.
2. `npm test` — все шаги зелёные (сейчас 37).
3. `vnmy.html` изменился, если менялся контент/код/стили.
4. Если добавляли вселенную/новеллу — проверьте `stories/index.json`: там новые
   `universes[].dir` и `novels[].dir`.
5. Если меняли версию — синхронно `js/version.js`, `package.json`, `sw.js`,
   `CHANGELOG.md`.
