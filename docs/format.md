# Формат вселенной и истории VNMY

Контент лежит двумя уровнями:

```
stories/<вселенная>/universe.json                    ← мир (группа новелл)
stories/<вселенная>/novels/<новелла>/story.json      ← одна новелла
stories/<вселенная>/novels/<новелла>/assets/*.webp   ← её картинки
```

Всё, что не указано, считается значением по умолчанию — файлы можно писать
минимально. Как добавить вселенную или новеллу пошагово — в
[ai-guide.md](ai-guide.md).

## Universe (`universe.json`)

```jsonc
{
  "schema": 1,
  "id": "silent-rails",          // = имя папки: латиница, цифры, дефис
  "title": "Тихие пути",         // заголовок на карточке
  "author": "VNMY demo",
  "description": "Одна строка о мире",
  "cover": "cover.webp",         // путь от папки вселенной; пусто → первая буква названия
  "accent": "#8fb8d8",           // цвет акцента этой вселенной
  "order": 1                      // порядок карточек: меньше = раньше
}
```

Вселенная, созданная в приложении, хранится в браузере (`localStorage`,
ключ `vnmy:universes`) и имеет те же поля. `baseUrl` подставляет загрузчик —
в файлах его писать не нужно.

## Story (`story.json`)

```jsonc
{
  "schema": 1,
  "id": "story_last_train",       // внутренний id; в локальной копии создаётся сам
  "title": "Последний поезд",
  "author": "VNMY demo",
  "description": "Одна строка для карточки в библиотеке",
  "cover": "assets/cover.webp",   // необязательно: покажется фон первой сцены, если пусто
  "accent": "#e0b072",            // цвет имён, вариантов, кнопок
  "universe": "silent-rails",     // id вселенной; пусто → «Без вселенной»
  "lang": "ru",                    // язык текста: переносы, кавычки, экранный диктор
  "media": [                       // необязательно: картинки, загруженные в редакторе
    { "id": "m1", "name": "фон", "url": "data:image/webp;base64,…", "kind": "image" }
  ],
  "vars": [ Var ],                 // необязательно: переменные истории
  "characters": [ Character ],
  "scenes": [ Scene ]
}
```

Все пути к картинкам считаются **от папки новеллы**: `assets/bg.webp` →
`stories/<вселенная>/novels/<новелла>/assets/bg.webp`. Абсолютные URL
(`https://…`), `data:` и пути, начинающиеся с `/`, используются как есть.

## Character

```jsonc
{
  "id": "anya",                  // уникальный, латиницей
  "name": "Аня",
  "color": "#e8c08a",            // цвет имени; пусто → акцентный цвет истории
  "sprites": {
    "neutral": "assets/anya-neutral.webp",
    "smile":   "assets/anya-smile.webp"
  }
}
```

Ключи `sprites` — это «эмоции». Первый ключ становится спрайтом по умолчанию.

## Scene

```jsonc
{
  "id": "sc_platform",
  "name": "Платформа",           // показывается карточкой при входе в сцену
  "bg": "assets/bg-platform.webp",
  "weather": "rain",             // none | rain | snow | dust | petals
  "cast": [ CastEntry ],         // кто стоит на сцене по умолчанию
  "steps": [ Step ]
}
```

### CastEntry

```jsonc
{
  "char": "anya",     // id персонажа
  "sprite": "smile",  // какая эмоция
  "pos": "center",    // left | center | right
  "scale": 1,         // 0.6…1.5
  "dim": false,       // затемнить (персонаж на втором плане)
  "hidden": false     // временно скрыть
}
```

### Step

```jsonc
{
  "id": "t1",
  "speaker": "anya",        // null → рассказчик (курсив, без имени)
  "text": "Реплика…",       // *курсив*, **жирный**, \n — перенос строки
  "spriteOverride": "smile",// эмоция говорящего именно на этом шаге
  "mood": "shake",          // "" | shake | flash | blush | dim | zoom
  "bg": "assets/other.webp",// сменить фон с этого шага
  "weather": "snow",        // сменить погоду с этого шага
  "cast": [ CastEntry ],    // заменить состав на сцене с этого шага
  "ask": {                  // спросить у игрока значение (имя героя и т. п.)
    "var": "имя",           // куда записать ответ — переменная типа text
    "label": "Как тебя зовут?",
    "placeholder": "имя",   // подсказка в поле
    "value": "Гость"        // что подставить, если игрок промолчит
  },
  "if": "sympathy >= 2",    // показывать шаг только при истинном условии
  "set": [                 // что записать в переменные при входе на шаг
    { "var": "sympathy", "op": "add", "value": 1 }
  ],
  "gotoIf": [              // условные переходы: проверяются по порядку, раньше `goto`
    { "when": "sympathy >= 3", "goto": "sc_dawn:t9" }
  ],
  "choices": [              // варианты выбора (можно без текста — будет экран выбора)
    { "text": "Пойти домой", "goto": "sc_home:t1", "if": "took_hand" }
  ],
  "goto": "sc_next:t1",     // куда идти после реплики
  "end": false,             // показать финальный экран
  "endTitle": "КОНЕЦ · Название концовки",
  "pause": 0                // пауза перед показом реплики, мс (0…4000)
}
```

Порядок разрешения после тапа:

1. `choices` — показываем варианты, ждём выбора (варианты с ложным `if` скрыты);
2. `end` — финальный экран (если у шага есть и выборы, и `end`, **сработают выборы** —
   редактор предупредит об этом);
3. `gotoIf` — первый переход с истинным `when`;
4. `goto` — переход;
5. иначе — следующий шаг этой сцены (шаги с ложным `if` пропускаются);
6. конец сцены → следующая сцена по порядку из `scenes`;
7. после последней сцены → финал «КОНЕЦ».

## Переменные и условия

Переменные живут на всю историю: флаги вроде «взял за руку», счётчики симпатии.
Если `vars` нет, история работает ровно как раньше — ни одного лишнего поля.

```jsonc
"vars": [
  { "name": "sympathy", "type": "number", "initial": 0 },  // number | bool | text
  { "name": "took_hand", "type": "bool", "initial": false }
]
```

`name` — латиница, цифры и `_` (`sympathy`, `took_hand`). Редактор сам чинит
недопустимые имена и переименовывает переменную во всех условиях истории.

| Поле шага | Смысл |
|---|---|
| `if` | шаг показывается только при истинном условии, иначе пропускается целиком |
| `set` | изменить переменные **при входе** на шаг (до показа текста) |
| `gotoIf` | условный переход: первый истинный `when` уводит на `goto` |

`choices[].if` скрывает вариант выбора, пока условие ложно.

### Операторы `set`

| `op` | Что делает | Пример |
|---|---|---|
| `set` | присвоить значение | `sympathy = 0` |
| `add` | прибавить (только числа) | `sympathy += 1` |
| `sub` | вычесть (только числа) | `sympathy -= 1` |
| `toggle` | переключить `bool` | `took_hand = !took_hand` |

### Условия

Условие — строка на маленьком безопасном языке. Он разбирается встроенным
парсером: никакого `eval`, `new Function` и доступа к странице, поэтому история,
скачанная со стороны, не может выполнить код.

```jsonc
"sympathy >= 2 && !took_hand"
"took_hand and sympathy > 1"
"name == \"Аня\""
""
```

| Что | Запись |
|---|---|
| Сравнения | `==` `!=` `>` `>=` `<` `<=` |
| Логика | `&&` `!` — или словами `and` `or` `not` |
| Группировка | `( )` |
| Числа | `2`, `0.5`, `-1` |
| Строки | `"Аня"`, `'Аня'` |
| Логические значения | `true`, `false` |
| Переменные | `sympathy`, `took_hand` |

Или пишется как `||` (двойная вертикальная черта) — удобно, если привыкли к C-подобному синтаксису.

Арифметики в условиях нет намеренно: `sympathy + 1 > 2` — ошибка, для этого есть `set`.
Пустое условие считается истинным. Опечатка в имени переменной не роняет игру:
условие просто не сработает, а редактор и вкладка «История → Проверка» покажут ошибку.

### Подстановка в текст

В `text`, `text` варианта и `endTitle` можно вставлять значения: `{sympathy}`,
`{took_hand}`. Числа и строки печатаются как есть, `bool` — как «да» / «нет».
Неизвестное `{имя}` остаётся видимым как есть, чтобы опечатку было легко заметить
(проверка истории сообщит о ней отдельно).

## Знакомство: `ask`

Шаг с полем `ask` спрашивает у игрока значение — так делают героя, чьё имя
неизвестно заранее:

```jsonc
{ "id": "t3", "ask": { "var": "имя", "label": "Как тебя зовут?", "value": "Гость" } }
```

Поверх сцены появляется карточка с полем ввода. Пока игрок не ответит, тап по
экрану ничего не листает; ответ записывается в переменную (поэтому она должна
быть объявлена в `vars`, лучше типа `text`) и сразу доступна в тексте:

```jsonc
{ "id": "t4", "speaker": "hero", "text": "— {имя}. Это я." }
```

Имя персонажа тоже подставляется из переменных, поэтому героя можно объявить
один раз:

```jsonc
{ "id": "hero", "name": "{имя}", "color": "#e0a86a" }
```

Вопрос задаётся один раз: если переменная уже заполнена (например, при загрузке
сохранения), карточка не появится. Если игрок промолчал, подставляется `value`.
В редакторе поле включается в шаге: «Логика → Спросить у игрока».

## Переходы (`goto`)

| Запись | Куда |
|---|---|
| `sc_train:t3` | сцена `sc_train`, шаг с id `t3` |
| `sc_train:3` | сцена `sc_train`, третий шаг (нумерация с 1) |
| `sc_train` | сцена `sc_train`, начало |
| `t3` | шаг `t3` в текущей сцене |

Ссылки на несуществующие шаги не ломают игру: движок покажет подсказку,
а редактор подсветит проблему во вкладке «История → Проверка».

`pause` задерживает показ именно текста: фон и спрайты меняются сразу, реплика
появляется через указанное время (полезно для «вдоха» перед важной фразой).

`cast`, `bg` и `weather` на шаге **накапливаются**: состояние сцены на шаге N —
это фон/погода/состав сцены плюс все переопределения шагов 1…N.
Поэтому поставить «персонаж ушёл» можно в любой момент, а не только в начале.

## Ассеты

| Тип | Размер | Примечание |
|---|---|---|
| Фон | 1080×1920, 9:16 | WebP q80 ≈ 150–250 КБ |
| Спрайт | высота 1500 px | обязательно с прозрачностью |
| Обложка новеллы | 9:14 | показывается в списке новелл |
| Обложка вселенной | 4:5 или 9:14 | показывается на главном экране |

Подготовить пачку картинок можно любым конвертером, например:

```bash
npx sharp-cli -i in.png -o bg.webp resize 1080 1920 --fit cover --format webp -q 80
npx sharp-cli -i hero.png -o hero-neutral.webp --format webp -q 92
```

Или просто загрузите картинки через редактор — он сам сожмёт их в WebP.

## Служебные поля

- `schema` — версия формата, сейчас `1`;
- `media` — только для картинок, добавленных через редактор;
- `createdAt`, `updatedAt` — время создания и последней правки, ставит редактор;
- `readOnly` в файлы не попадает: встроенные новеллы помечаются при загрузке;
- `baseUrl` подставляет загрузчик, в файлах его писать не нужно;
- `_builtin` — служебная метка сборки (`<вселенная>/novels/<новелла>`).

Сохранения (автосейв, «продолжить» и три ручных слота) вместе с позицией хранят
значения переменных и журнал прочитанных реплик — поэтому после закрытия вкладки
история продолжается с теми же флагами, а журнал не обнуляется.

## Экспорт и бэкап

| Что | Формат | Зачем |
|---|---|---|
| «Экспорт с картинками» | тот же `story.json`, но все картинки вшиты как `data:image/…` и `baseUrl: ""` | один файл переносится на любое устройство и открывается без папки `stories/` |
| «Экспорт JSON» | `story.json` с путями `assets/…` | чтобы положить новеллу в `stories/<вселенная>/novels/<новелла>/` |
| «Экспорт вселенной» (меню «⋯») | `{ "format": "vnmy-universe", "universe": {…}, "novels": [ … ] }`, картинки вшиты | перенести мир целиком: все новеллы в одном файле |
| «Бэкап» (в библиотеке) | `{ "format": "vnmy-backup", "universes": [ … ], "stories": [ … ] }` | сохранить все свои вселенные и новеллы одним файлом |

Импорт понимает все четыре варианта: одиночную новеллу, портируемую новеллу,
вселенную целиком и бэкап. Портируемый экспорт помечается полями
`portable: true` и `exportedAt`.

Если при импорте вселенной её `id` уже занят встроенной вселенной, новые
новеллы просто добавятся в неё. Новелла без вселенной, импортированная внутри
экрана вселенной, попадает в эту вселенную.
