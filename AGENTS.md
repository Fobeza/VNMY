# AGENTS.md — инструкция для ИИ-агента

Это движок визуальных новелл VNMY: статический сайт на чистом HTML/CSS/JS.
Контент — JSON-файлы в `stories/`. Сборка нужна только чтобы получить
файлы для запуска без сервера.

**Если задача «добавить/поправить новеллу» — читайте [docs/ai-guide.md](docs/ai-guide.md).
Если задача «понять, где что лежит» — [docs/structure.md](docs/structure.md).
Схема JSON — [docs/format.md](docs/format.md).**

## Главное про контент

```
stories/<вселенная>/universe.json                  ← мир: название, описание, обложка
stories/<вселенная>/novels/<новелла>/story.json    ← одна новелла (сценарий)
stories/<вселенная>/novels/<новелла>/assets/*.webp ← её картинки
```

- Одна вселенная = одна папка в `stories/`. Одна новелла = одна папка в
  `stories/<вселенная>/novels/`.
- В `story.json` поле `"universe": "<id вселенной>"` — оно должно совпадать с
  папкой; сборка всё равно проставит его по папке.
- `id` вселенной = имя её папки: только латиница, цифры и дефисы.
- Папки и файлы, начинающиеся с `_`, сборка игнорирует (`stories/_template`).
- Пути к картинкам в `story.json` относительные, от папки новеллы: `assets/bg.webp`.
- Новая вселенная/новелла = новые папки. Ничего в коде менять не нужно.

## Обязательные команды

```bash
npm install                     # один раз: esbuild + jsdom
npm run build                   # пересобирает stories/index.json, bundle.js,
                                # stories/builtin.js и vnmy.html
npm test                        # 41 интеграционный шаг (jsdom)
```

`npm run build` обязателен после **любой** правки в `stories/`, `js/` или `css/`:
тест «файлы для двойного щелчка собраны и свежие» сравнивает собранные файлы
побайтово и падает, если они устарели.

## Что нельзя трогать руками

Эти файлы генерируются — правки в них потеряются при следующей сборке:

- `bundle.js`, `stories/builtin.js`, `vnmy.html` — `npm run build`;
- `stories/index.json` — манифест библиотеки, тоже `npm run build`.

`vnmy.html` — это доставка на телефон: один файл со всем внутри. После сборки
его надо перекачать на устройство, чтобы увидеть изменения.

## Правила проекта

- Никаких фреймворков, бандлеров в рантайме, CDN и внешних шрифтов:
  только ванильные `js/*.js` (ES-модули), один `index.html`, CSS в `css/`.
- Игровой контент для сборки хранится только в JSON. Не зашивайте новеллы в `js/`;
  синтетическая фикстура в `tests/fixtures/` используется только тестами и не попадает в сборку.
- Всё работает офлайн, в том числе с `file://` (поэтому и есть сборка в
  обычные скрипты: с диска браузер не грузит модули и не делает `fetch`).
- UI лаконичный, вертикальный (9:16), мобильный первый.
- Спрайты сохраняют пропорции: ширина следует за картинкой, высота `64cqh`.
- Версия живёт в `js/version.js`, `package.json`, `package-lock.json`, `sw.js`,
  `CHANGELOG.md` — менять синхронно.

## Минимальный сценарий «добавить новеллу»

1. Скопировать `stories/_template/novels/novel-example` →
   `stories/<вселенная>/novels/<имя-новеллы>`.
2. Заменить `story.json` и картинки в `assets/`.
3. `npm run build && npm test`.
4. Убедиться, что новелла видна: `stories/index.json` → нужная вселенная → `novels`.

Проверить глазами можно через `python3 -m http.server 8000` → `http://localhost:8000`
или открыв `vnmy.html` (он самодостаточный).
