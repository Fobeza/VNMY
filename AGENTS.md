# AGENTS.md — работа с VNMY

VNMY — мобильный браузерный движок визуальных новелл с вертикальной сценой 9:16. Встроенного редактора нет. В репозитории хранится только движок и его сборка. Новеллы в репозиторий не добавляются: они живут отдельно и загружаются в приложение кнопкой «Импорт» из файла `.vnmy`.

## Где живут новеллы

- Новелла хранится у владельца отдельно от репозитория: папкой или файлом `.vnmy`. Файл `.vnmy` — это zip той же папки, его можно распаковать любым архиватором. Если вас попросили поправить новеллу, а её папки или `.vnmy` нет в рабочем каталоге, попросите владельца прислать файл. Не восстанавливайте новеллу из истории git: её оттуда удалили.
- Распакуйте `.vnmy` вне репозитория, например во временную папку. Не кладите новеллы в `stories/` и не коммитьте их: папки `stories/*/` и файлы `*.vnmy` перечислены в `.gitignore`.
- Папка вселенной: `universe.json` и `novels/<новелла>/story.json`. Обязательный `id` вселенной совпадает с именем папки. Используйте строчные латинские буквы, цифры и дефисы. Минимальный `universe.json` для папки `example-world`:

```json
{"id":"example-world","title":"Пример мира"}
```

- Можно упаковать и одну новеллу без вселенной: папку со `story.json` и `assets/`. Тогда вселенную задаёт поле `universe` новеллы.
- В `story.json` укажите уникальный `id` новеллы и `universe` с ID мира. Сохраняйте существующие ID вселенной, новеллы, сцен, шагов и персонажей при правках. Сохранения и переходы используют эти идентификаторы. Повторный импорт новеллы с тем же `id` обновляет её у игрока и сохраняет его прогресс.
- Графика новеллы лежит в `assets/` рядом с её `story.json`. Используйте относительные пути от папки новеллы, например `assets/backgrounds/gate-day.webp`. Путь к обложке в `universe.json` считается от папки мира. Соблюдайте регистр имён, не используйте `../` и абсолютные пути. Фоны готовьте под сцену 9:16, спрайты — с прозрачностью, формат — WebP. Необработанные исходники кладите в папки `raw/` или с именем на `_`: упаковка их пропускает.
- Проверка и упаковка новеллы из любой папки:

```sh
npm run check -- путь/к/вселенной   # сценарий, картинки, маршруты
npm run pack -- путь/к/вселенной путь/к/новелла.vnmy
```

`pack` сначала выполняет ту же проверку и не создаёт файл, если она не прошла. Готовый `.vnmy` отдайте владельцу. Он загружает файл в приложение кнопкой «Импорт».

## Как менять сценарий

История содержит `scenes`, сцена — `steps`. Движок начинает с первой сцены. У шага `text` — реплика, `speaker` — ID персонажа или `null` для рассказчика. В `choices` укажите текст каждого варианта и его цель `goto`. Используйте ссылки вида `сцена:шаг`. Для завершения ветки поставьте `"end": true`. В примере ниже фон опущен, поэтому валидатор выдаст одно предупреждение.

```json
{
  "schema": 1,
  "id": "example-story",
  "title": "У ворот",
  "universe": "example-world",
  "scenes": [
    {
      "id": "gate",
      "name": "Ворота",
      "steps": [
        {
          "id": "arrival",
          "speaker": null,
          "text": "Передо мной ворота.",
          "choices": [
            {"text": "Войти", "goto": "gate:enter"},
            {"text": "Уйти", "goto": "gate:leave"}
          ]
        },
        {"id": "enter", "text": "Я толкнул створку.", "end": true},
        {"id": "leave", "text": "Я повернул обратно.", "end": true}
      ]
    }
  ]
}
```

- Фон задаётся полем `bg` сцены или шага. В `characters[].sprites` сопоставьте ключ эмоции с путём к изображению. В `cast` укажите `char` (ID персонажа), `sprite` (ключ эмоции) и `pos` (`left`, `center` или `right`). Поле `cast` на шаге заменяет состав сцены целиком.
- Перед добавлением условий, переменных, эффектов и переходов сверяйтесь с [js/format.js](js/format.js) и [js/expr.js](js/expr.js).

### Справочник полей

Полная схема и значения по умолчанию описаны в начале [js/format.js](js/format.js). Неизвестные поля сцен, шагов и персонажей движок молча отбрасывает, поэтому не придумывайте новые.

- **Новелла:** `id`, `title`, `universe`, `author`, `description`, `cover` (обложка), `accent` (цвет акцента, например `"#e0b072"`), `lang` (по умолчанию `"ru"`), `genres` (массив жанров), `soundtrack` (массив `{title, src}`), `staging`, `vars`, `characters`, `scenes`.
- **Персонаж:** `id`, `name`, `color` (цвет имени), `sprites`. Герой от первого лица — персонаж без `sprites`, он говорит из-за кадра.
- **Сцена:** `id`, `name` (показывается карточкой при входе), `act` (строка над названием), `card: false` (без карточки), `bg`, `music`, `weather`, `cast`, `steps`.
- **Шаг:**
  - `text` — реплика;
  - `speaker` — ID персонажа;
  - `bg`, `weather`, `cast` — меняют сцену начиная с этого шага;
  - `music` — сменить музыку, пустая строка останавливает; `sound` — разовый звук шага; `voice` — голосовая дорожка реплики;
  - `spriteOverride` — эмоция говорящего только на этом шаге;
  - `mood` — эффект: `shake`, `flash`, `blush`, `dim`, `zoom`;
  - `pause` — пауза перед репликой, до 4000 мс;
  - `if` — условие показа шага;
  - `set` — изменение переменных;
  - `gotoIf` — условные переходы;
  - `choices` — варианты выбора;
  - `goto` — переход после шага;
  - `ask` — вопрос игроку;
  - `end` и `endTitle` — концовка;
  - `note` — заметка автора, игроку не показывается.
- **Погода:** `none`, `rain`, `snow`, `dust`, `petals`.

### Порядок прохождения

- Шаги идут подряд. После последнего шага сцены начинается следующая сцена по порядку в массиве `scenes`. Если сцена последняя и у шага нет `end`, история закончится экраном «КОНЕЦ», а валидатор предупредит об этом.
- Шаг с ложным `if` пропускается целиком: его `set`, `bg` и `cast` не применяются.
- После реплики проверяются, в этом порядке: доступные `choices`, затем `end`, затем первое сработавшее правило `gotoIf`, затем `goto`, затем следующий шаг.
- Ссылка в `goto` может быть такой:
  - `"сцена:шаг"` — шаг по ID, используйте этот вид;
  - `"сцена:3"` — третий шаг сцены, нумерация с единицы;
  - `"шаг"` — шаг текущей сцены;
  - `"сцена"` — начало сцены.
- Если все варианты выбора условные и ни один не доступен, кнопок не будет и история пойдёт дальше. Добавляйте вариант без условия.
- Текст шага с `"end": true` показывается на экране концовки под заголовком `endTitle`.

### Переменные, условия и текст

- Объявите переменную в `vars`: `{"name": "trust", "type": "number", "initial": 0}`. Типы: `number`, `bool`, `text`. Имя состоит из букв, цифр и `_` и не начинается с цифры; некорректное или повторное имя валидатор считает ошибкой. Необъявленная переменная в условии считается ошибкой.
- `set`: `[{"var": "trust", "op": "add", "value": 1}]`. Операции: `set`, `add`, `sub` и `toggle` (только для `bool`). Для флага `add` включает, `sub` выключает; для текста `add` дописывает, а `sub` запрещён.
- Условия в `if`, `gotoIf[].when` и `choices[].if`: `trust >= 2 && met_anya`, `not seen or (route == "лес")`, `trust > -1`. Операторы: `== != > >= < <= && || !`, слова `and`, `or`, `not` и скобки. Числа могут быть отрицательными. Арифметики в условиях нет. Пустое `gotoIf[].when` — ошибка: для безусловного перехода используйте `goto`.
- `ask`: `{"var": "hero", "label": "Как тебя зовут?", "placeholder": "Имя", "value": "Гость"}`. Вопрос появляется, только пока переменная пустая. `value` — ответ по умолчанию. Используйте текстовую переменную: для `number` и `bool` ответ приводится к их типу.
- В `text`, `choices[].text`, `endTitle` и имени персонажа `{имя_переменной}` заменяется значением переменной. Разметка реплики: `*курсив*`, `**жирный**`, `\n` — перенос строки. Мысли героя принято писать в скобках от рассказчика (`speaker: null`).

### Расстановка персонажей

- На сцене одновременно не больше трёх видимых персонажей, по одному на каждую позицию `left`, `center` и `right`. Валидатор предупреждает о двух персонажах в одной позиции, а состав больше трёх считает ошибкой. При чтении старого файла движок показывает не более трёх видимых персонажей со спрайтами, по одному на позицию. Неизвестная эмоция в `sprite` или `spriteOverride` считается ошибкой.
- Персонаж со спрайтами, который говорит в шаге, должен стоять в текущем составе. Иначе валидатор выдаст предупреждение. Персонаж без спрайтов, например герой от первого лица, может говорить из-за кадра.
- Состав переносится на следующие шаги, пока очередной шаг не задаст новый `cast`. Чтобы убрать персонажа, задайте `cast` без него. Если на шаг ведут переходы из разных мест (`goto`, `choices`, `gotoIf`), задайте на нём полный `cast`, иначе на сцене останутся персонажи из предыдущей ветки.
- Поле новеллы `staging` выбирает режим расстановки. Значение `"stable"` действует по умолчанию, его достаточно для новых новелл. Состав раскладывается по сцене равномерно: один персонаж — в центре, двое — слева и справа, трое — на всех трёх местах. Порядок слева направо сохраняется: стоящие персонажи не перебегают друг через друга, а при изменении их числа плавно сдвигаются. Новый персонаж встаёт со стороны своей позиции из `cast`. Поэтому в `cast` достаточно перечислить, кто сейчас на сцене. Чтобы персонаж специально перешёл на другое место, добавьте ему `"move": true`; если там стоит другой персонаж, они меняются местами. Шаг с `move` расставляет персонажей по их позициям без выравнивания. При `"staging": "manual"` позиции берутся из `cast` буквально. Этот режим включён у новеллы `sovyonok`. В режиме `manual` не сдвигайте всех персонажей при каждом новом говорящем: каждый сдвиг заметен как скольжение спрайта через экран.
- Движок сам показывает, кто участвует в разговоре (`conversationFocus` в [js/engine.js](js/engine.js)). Говорящий персонаж ярче остальных и стоит поверх соседей. Роль в разговоре не меняет масштаб или положение корпуса. Когда говорит герой без спрайта, последний говоривший собеседник остаётся почти ярким. Молчащие участники приглушены. Персонаж, который молчит 7 шагов подряд, становится фоном: он темнее, но остаётся на той же высоте. Это подсказка, что его пора убрать из `cast`. Чтобы принудительно затемнить персонажа, поставьте ему `"dim": true`.

### Единый вид сцены

- На телефоне сцена заполняет доступную высоту без полос; на большом экране сохраняется предпросмотр 9:16. Вариант А: реплика поверх сцены, варианты ответа ниже реплики, панель чтения у нижнего края. Интерфейс универсальный: тёмные нейтральные панели, акцент `#8d9af2`, без декора конкретной новеллы. `accent` истории сохраняется в данных для совместимости, оболочка использует единый акцент.
- Для одиночного персонажа задавайте `center`, для пары — `left` и `right`, для тройки — все три позиции. В режиме `stable` движок выравнивает состав так сам: при входе или уходе участника остальные плавно сдвигаются, сохраняя порядок. Изменение роли говорящего и количества ответов не меняет геометрию спрайтов.
- Читательский масштаб спрайтов задаётся в «Настройки → Текст → Масштаб персонажей» или в меню игры «Масштаб персонажей». Диапазон 50–300%, значение общее для всех новелл и входит в бэкап настроек. Множитель `spriteScale` — настройка приложения, а не поле `story.json`: умножается на авторский `cast[].scale` и не переписывает сценарий, позиции или сохранённый состав. В режиме настройки реплика временно скрыта; закрытие, касание подложки и Escape возвращают её.
- Все эмоции одного персонажа готовьте на одинаковом прозрачном холсте с совпадающим положением головы и корпуса. Разные ширины изображений вписываются в один прямоугольник, но неровную обрезку самого рисунка нужно исправлять в ассетах: движок не угадывает положение тела по изображению. `scale` сохраняйте одинаковым между эмоциями; используйте его для разницы роста персонажей.
- Панели сцены полупрозрачные: фон идёт от края до края, низ спрайта мягко растворяется. Варианты выбора — отдельные кнопки под репликой. Имена в журнале окрашены цветом персонажа (`color`).
- `cast` заменяется целиком; `speaker` выделяет говорящего яркостью; `spriteOverride` меняет только эмоцию. Новых полей для этого не требуется. Старые ID и сохранения совместимы.
- Галерея открывает только фактически показанные фоны (`visual.bg`); непрочитанные ветки не раскрываются. Открытые изображения входят в бэкап. Музыкальные дорожки открываются при прохождении соответствующей сцены. Опциональные `scene.music`, `step.music`, `step.sound`, `step.voice` — пути к файлам внутри .vnmy; `soundtrack` задаёт их названия для музыкальной галереи. Поддерживаются mp3, wav, ogg, m4a, aac в пределах возможностей браузера. Удалённые дорожки требуют CORS. Пустая строка `music` останавливает музыку; при обычном переходе на новый шаг голос и эффект предыдущего шага останавливаются. В меню приостановлены голос и эффект, музыка продолжает играть; уход в фон учитывает настройку «Звук в фоне». Старые файлы без аудиополей совместимы.

Дизайн страниц и сверка с выбранными референсами описаны в [docs/ui-reference.md](docs/ui-reference.md).

## Как менять движок и проверять правки

- Разметка — `index.html`, стили — `css/`, логика — `js/`. `js/engine.js` отвечает за сцену, `js/session.js` — за состояние истории, `js/player.js` — за экран прохождения. Импорт `.vnmy` описан в `js/zip.js` и `importPackage` в `js/store.js`. Картинки импортированных новелл хранятся в IndexedDB (`js/persistence.js`).
- `bundle.js`, `vnmy.html`, `stories/index.json` и `stories/builtin.js` генерирует сборка. По умолчанию она собирает только движок, без новелл. После изменений в `js/`, `css/` или `index.html` пересоберите и включите изменившиеся результаты в тот же коммит. Сборка `npm run build -- --with-stories` встраивает папки из `stories/` и нужна только для личного файла. Её результаты не коммитьте.

```sh
npm ci
npm run build
npm run check
npx playwright install chromium
npm run check:browser  # настоящие размеры, масштаб и скриншоты четырёх размеров экрана
```

- При заметном изменении движка поднимите версию сразу в `package.json`, `package-lock.json`, `js/version.js` и `sw.js` (`VERSION`). Иначе установленное как приложение может держать старые файлы в кэше.
- GitHub Actions (`.github/workflows/check.yml`) на каждый pull request и push в `main` выполняет сборку и `npm run check`. Проверка падает, если собранные файлы не закоммичены, если в репозитории оказалась новелла или если файл больше 1 МБ. Всё равно запускайте `npm run build` и `npm run check` перед коммитом: так ошибки находятся сразу.

Запустите `npm start` и откройте `http://localhost:8000` либо откройте собранный `vnmy.html` с диска, затем импортируйте новеллу из `.vnmy`. Для новеллы проверьте изменённую сцену, каждый затронутый выбор и загрузку её графики. При изменении логики прохождения проверьте продолжение с сохранения.

### Автоматическая проверка маршрутов

Для сюжетной новеллы добавьте `routes.json` рядом со `story.json`. Он едет внутри `.vnmy`, и приложение его не читает. Опишите хотя бы один маршрут к каждой запланированной концовке. Вот маршрут для примера «У ворот»:

```json
[
  {
    "name": "Войти в лагерь",
    "actions": [
      {"at": "gate:arrival", "resume": true},
      {"at": "gate:arrival", "choose": "Войти"}
    ],
    "end": "gate:enter"
  }
]
```

- `actions` перечисляет действия в порядке прохождения. Адрес `at` — `сцена:шаг`. Обычные реплики проверка пролистывает сама. `choose` — точный текст доступной кнопки, с учётом подстановки переменных. Для шага с вводом укажите `answer` со строкой ответа.
- `resume: true` закрывает и снова открывает новеллу через автосохранение. Проверка сравнивает позицию, переменные, журнал и состояние сцены. Ставьте такую точку до финала, желательно после выбора или изменения переменной.
- `end` — адрес шага с `"end": true`. Необязательный объект `vars` задаёт ожидаемые значения переменных в финале, например `{"trust": 2}`.

`npm run check -- <папка>` и `npm run pack` запускают эти маршруты через плеер. Для новелл без `routes.json` выполняется только проверка сценария и ассетов. Условия, для которых маршрут не описан, нужно проверить отдельно.

## Работа с git

- Работайте в отдельной ветке от свежего `main`. В `main` изменения попадают через pull request.
- История репозитория очищена от новелл и тяжёлых сборок. Не делайте `push` из клонов, созданных до очистки, и не восстанавливайте удалённые файлы из старых коммитов.
- Не коммитьте новеллы, `.vnmy`, архивы и файлы больше 1 МБ. Собранный `vnmy.html` весит около 150 КБ. Если он стал заметно больше, значит в сборку попала новелла.
