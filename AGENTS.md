# AGENTS.md — работа с VNMY

VNMY — мобильный браузерный движок визуальных новелл с вертикальной сценой 9:16. Встроенного редактора нет. В репозитории хранятся исходники движка, его сборка и только тот игровой контент, который попросили добавить. Примеры ниже служат справкой.

## Куда добавлять новеллы и графику

- Вселенная: `stories/<мир>/universe.json`. Обязательный для проекта `id` совпадает с именем папки. Используйте строчные латинские буквы, цифры и дефисы. Минимальный файл для папки `example-world`:

```json
{"id":"example-world","title":"Пример мира"}
```

- Новелла: `stories/<мир>/novels/<новелла>/story.json`. Укажите уникальный `id` новеллы и `universe` с ID мира. Сохраняйте существующие ID вселенной, новеллы, сцен, шагов и персонажей при правках. Сохранения и переходы используют эти идентификаторы.
- Графика новеллы: `assets/` рядом с её `story.json`. Используйте относительные пути от папки новеллы, например `assets/backgrounds/gate-day.webp`. Путь к обложке в `universe.json` считается от папки мира. Соблюдайте регистр имён, не используйте `../` и абсолютные пути. Фоны готовьте под сцену 9:16, спрайты — с прозрачностью. Для файлов в репозитории используйте WebP. Не добавляйте архивы и необработанные исходники.

## Как менять сценарий

История содержит `scenes`, сцена — `steps`. Движок начинает с первой сцены. У шага `text` — реплика, `speaker` — ID персонажа или `null` для рассказчика. В `choices` укажите текст каждого варианта и его цель `goto`. Используйте ссылки вида `сцена:шаг`. Для завершения ветки поставьте `"end": true`. В примере ниже фон опущен, поэтому валидатор выдаст одно предупреждение.

```json
{
  "schema": 1,
  "id": "example-story",
  "title": "У ворот",
  "universe": "example-world",
  "scenes": [
    {
      "id": "gate",
      "name": "Ворота",
      "steps": [
        {
          "id": "arrival",
          "speaker": null,
          "text": "Передо мной ворота.",
          "choices": [
            {"text": "Войти", "goto": "gate:enter"},
            {"text": "Уйти", "goto": "gate:leave"}
          ]
        },
        {"id": "enter", "text": "Я толкнул створку.", "end": true},
        {"id": "leave", "text": "Я повернул обратно.", "end": true}
      ]
    }
  ]
}
```

- Фон задаётся полем `bg` сцены или шага. В `characters[].sprites` сопоставьте ключ эмоции с путём к изображению. В `cast` укажите `char` (ID персонажа), `sprite` (ключ эмоции) и `pos` (`left`, `center` или `right`). Поле `cast` на шаге заменяет состав сцены целиком.
- Перед добавлением условий, переменных, эффектов и переходов сверяйтесь с [js/format.js](js/format.js) и [js/expr.js](js/expr.js).

### Расстановка персонажей

- На сцене одновременно не больше трёх видимых персонажей, по одному на каждую позицию `left`, `center` и `right`. Валидатор предупреждает о двух персонажах в одной позиции и о составе больше трёх. Неизвестная эмоция в `sprite` или `spriteOverride` считается ошибкой.
- Персонаж со спрайтами, который говорит в шаге, должен стоять в текущем составе. Иначе валидатор выдаст предупреждение. Персонаж без спрайтов, например герой от первого лица, может говорить из-за кадра.
- Состав переносится на следующие шаги, пока очередной шаг не задаст новый `cast`. Чтобы убрать персонажа, задайте `cast` без него. Если на шаг ведут переходы из разных мест (`goto`, `choices`, `gotoIf`), задайте на нём полный `cast`, иначе на сцене останутся персонажи из предыдущей ветки.
- Не сдвигайте всех персонажей при каждом новом говорящем. Пусть оставшиеся стоят на прежних позициях, а новый персонаж займёт освободившееся место. Каждый сдвиг заметен как скольжение спрайта через экран.
- Движок сам показывает, кто участвует в разговоре (`conversationFocus` в [js/engine.js](js/engine.js)). Говорящий персонаж ярче остальных, немного крупнее и стоит поверх соседей. Когда говорит герой без спрайта, последний говоривший собеседник остаётся почти ярким. Молчащие участники приглушены. Персонаж, который молчит 7 шагов подряд, становится фоном: он темнее и немного ниже. Это подсказка, что его пора убрать из `cast`. Чтобы принудительно затемнить персонажа, поставьте ему `"dim": true`.

## Как менять движок и проверять правки

- Разметка — `index.html`, стили — `css/`, логика — `js/`. `js/engine.js` отвечает за сцену, `js/session.js` — за состояние истории, `js/player.js` — за экран прохождения. Для правок текста и графики новеллы меняйте её JSON и файлы ассетов.
- `bundle.js`, `vnmy.html`, `stories/index.json` и `stories/builtin.js` генерирует сборка. После изменений в `stories/`, `js/`, `css/` или `index.html` пересоберите и включите изменившиеся результаты в тот же коммит.

```sh
npm ci
npm run build
npm run check
```

Запустите `npm start` и откройте `http://localhost:8000` либо откройте собранный `vnmy.html` с диска. Для новеллы проверьте изменённую сцену, каждый затронутый выбор и загрузку её графики. При изменении логики прохождения проверьте продолжение с сохранения.

### Автоматическая проверка маршрутов

Для сюжетной новеллы добавьте `routes.json` рядом со `story.json`. Опишите хотя бы один маршрут к каждой запланированной концовке. Вот маршрут для примера «У ворот»:

```json
[
  {
    "name": "Войти в лагерь",
    "actions": [
      {"at": "gate:arrival", "resume": true},
      {"at": "gate:arrival", "choose": "Войти"}
    ],
    "end": "gate:enter"
  }
]
```

- `actions` перечисляет действия в порядке прохождения. Адрес `at` — `сцена:шаг`. Обычные реплики проверка пролистывает сама. `choose` — точный текст доступной кнопки, с учётом подстановки переменных. Для шага с вводом укажите `answer` со строкой ответа.
- `resume: true` закрывает и снова открывает новеллу через автосохранение. Проверка сравнивает позицию, переменные, журнал и состояние сцены. Ставьте такую точку до финала, желательно после выбора или изменения переменной.
- `end` — адрес шага с `"end": true`. Необязательный объект `vars` задаёт ожидаемые значения переменных в финале, например `{"trust": 2}`.

`npm run check` запускает эти маршруты через плеер. Для новелл без `routes.json` выполняется только проверка сценария и ассетов. Условия, для которых маршрут не описан, нужно проверить отдельно.
